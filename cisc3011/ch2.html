第 2 章 · 點運算與影像合成

一次只處理一個像素

📌 一句話說完 點運算 = 新的像素值只跟「同一個位置」的舊像素值有關，完全不看旁邊的鄰居。
本章內容
  1. 什麼是點運算
  2. 五種基本點運算
  3. Gamma 冪次轉換（必考）
  4. 影像相加相減
  5. Alpha 混合（必考）
  6. 考點整理

1. 什麼是點運算

s = T(r) r = 原本的像素值，s = 新的像素值，T = 轉換函數

關鍵在於：算 s 的時候只用到同一位置的 r。所以你可以寫成一個簡單的雙重迴圈：

for i in range(H):
    for j in range(W):
        out[i][j] = T(img[i][j])   # 只看 img[i][j]，不看鄰居
✅ 怎麼分辨是不是點運算 問自己一句：「算這一格的新值，需要偷看旁邊的格子嗎？」
不用 → 點運算（第 2、3 章）。需要 → 鄰域運算／濾波（第 4、5、6 章）。
所以模糊、銳化、邊緣偵測都不是點運算，因為要看鄰居。

另外還分兩種：

  • Homogeneous（齊次）：所有像素用同一條規則。例如整張圖都 +50。
  • Non-homogeneous（非齊次）：規則跟位置有關。例如照片四角壓暗（vignette）。

2. 五種基本點運算

① 加亮 / 對比（線性）

s = a · r + b b 管亮度（整體平移）、a 管對比（拉開或壓縮）

a > 1 對比變強，a < 1 對比變弱；b > 0 變亮，b < 0 變暗。

② 箝位 Clamping

算完可能跑出 0~255 之外，必須夾回來，否則會溢位變成亂碼。

s = min(255, max(0, s))
⚠️ 程式陷阱（作業也考過） uint8 型別最大只到 255。如果 200 + 100 不先轉成浮點數，結果不是 300 也不是 255， 而是會「繞回去」變成 44（300 − 256）。所以運算前要先轉 float，最後再 clip 回 0~255。

③ 反相 Negative

s = (L − 1) − r ＝ 255 − r L = 灰階級數，8-bit 時 L−1 = 255

最亮變最暗、最暗變最亮，就像底片。醫學影像（X 光）常用，因為人眼對暗背景上的亮細節比較敏感。

④ 二值化 Thresholding

s = 1（若 r > T）；s = 0（若 r ≤ T）

把灰階圖變成只有黑白兩色。這是第 6 章形態學的前置步驟——形態學只處理二值圖。

⑤ 對數轉換 Log

s = c · log(1 + r) 壓縮動態範圍：暗部被拉開、亮部被壓扁

3. Gamma 冪次轉換

s = c · rγ γ（gamma）決定變亮還是變暗
⚠️ 最容易記反的地方，務必弄懂 γ < 1 → 變亮　　γ > 1 → 變暗　　γ = 1 → 不變

為什麼？先把像素正規化到 0~1 之間（除以 255），然後想一個具體數字，例如 r = 0.25：

γ算式結果比原本 0.25…
0.50.250.5 = √0.250.50變大 → 變亮 ☀️
1.00.2510.25不變
2.00.2520.0625變小 → 變暗 🌙

記憶法：0 到 1 之間的小數，次方越大結果越小（0.5 的平方是 0.25，變小了）。所以 γ 大 = 變暗。

💡 為什麼現實中需要 Gamma 校正 螢幕的輸出亮度和輸入電壓不是線性關係（大約是 2.2 次方），而且人眼對暗部變化比較敏感（Weber's law）。 所以拍攝時先做 γ ≈ 1/2.2 的預校正，顯示時螢幕再做 γ ≈ 2.2，兩者抵銷後看起來才正常。
例題：r = 100（8-bit），c = 1，γ = 2，求 s

正確做法（先正規化）：
r' = 100 / 255 = 0.392
s' = 0.3922 = 0.1537
s = 0.1537 × 255 ≈ 39

錯誤做法：直接算 100² = 10000 → 遠遠超過 255，整張圖會爆掉。
所以冪次轉換一定要先把值縮到 0~1 再做次方，最後再乘回 255。（作業 hw2 考過這個坑）

4. 影像相加相減

運算公式用途
平均多張s = (I₁+I₂+…+IN) / N 降雜訊。雜訊是隨機的會互相抵銷，訊號固定會留下。
平均 N 張後，雜訊標準差變成原本的 1/√N。（平均 4 張 → 雜訊減半）
相減s = I₁ − I₂ 找差異：監視器背景相減抓移動物體、工業檢測找瑕疵、醫學血管攝影。
絕對差s = |I₁ − I₂| 同上，但不管誰大誰小都看得到差異（負數不會被截掉）。

5. Alpha 混合（影像合成）

要把兩張圖疊在一起，直接貼上去（copy-paste）會留下一條很硬的長方形接縫。解法是加一個透明度通道 α。

I = α · F + (1 − α) · B F = 前景(foreground)、B = 背景(background)、α ∈ [0, 1]
α 的值看到什麼
α = 1100% 前景（完全不透明）
α = 0100% 背景（前景完全透明）
0 < α < 1按比例混合（半透明）← 柔和過渡就是靠這個
✅ 為什麼公式要用 (1 − α) 因為兩個權重加起來必須 = 1，這樣亮度才不會變。 如果寫成 α·F + α·B，當 α=1 時結果會是兩張圖相加，亮度爆掉。

Feathering（羽化）

關鍵不是 α 的值，而是讓 α 從 1 平滑地降到 0（通常把二值遮罩用高斯模糊一下）。 過渡帶的寬度叫 window size：

  • 太窄 → 還是看得到接縫（seam）
  • 太寬 → 兩張圖重疊處出現「鬼影」（ghosting），人物會半透明
  • 最佳 ≈ 最大明顯特徵的尺寸
💡 進階：Pyramid Blending 更好的做法是把影像拆成不同頻率層（Laplacian pyramid），每一層用不同寬度的過渡帶： 粗糙的低頻用寬過渡、細節的高頻用窄過渡，就能同時避免接縫和鬼影。 （概念題，知道「不同頻率用不同過渡寬度」就夠。）
例題：F = 200、B = 80、α = 0.25，求混合結果

I = 0.25 × 200 + (1 − 0.25) × 80
= 50 + 0.75 × 80
= 50 + 60 = 110

檢查合理性：α 只有 0.25，所以結果應該比較靠近背景 80，而 110 確實比較靠近 80（而不是 200）。✓

⚠️ 程式陷阱（hw2 考過） 彩色圖是 (H, W, 3)，但遮罩 α 只有 (H, W)，形狀對不上不能直接相乘。 要用 alpha[:, :, np.newaxis] 補一個維度變成 (H, W, 1)， numpy 的 broadcasting 才會自動套用到 R、G、B 三個通道。

6. 考點整理

✅ 本章一定要會
  1. 點運算定義：只看同位置像素（會拿來跟濾波對比考）
  2. 反相 s = 255 − r；二值化；線性 s = ar + b
  3. γ < 1 變亮、γ > 1 變暗，且計算前要先正規化到 0~1
  4. 平均 N 張 → 雜訊降為 1/√N
  5. I = αF + (1−α)B，兩權重和必為 1
  6. 過渡太窄→接縫；太寬→鬼影

小測驗

Q1. 下列哪一個不是點運算？
影像反相 s = 255 − r
Gamma 轉換 s = c·r^γ
3×3 平均模糊
二值化
3×3 平均模糊需要看周圍 8 個鄰居才能算出中心的新值，屬於鄰域運算（濾波），不是點運算。其他三個都只用到同一位置的像素值。
Q2. 一張照片太暗，要用冪次轉換把它變亮，γ 應該選？
γ = 0.4
γ = 1.0
γ = 1.8
γ = 2.5
γ < 1 會變亮，所以選 0.4。驗算：0.250.4 ≈ 0.57 > 0.25，確實變亮了。
Q3. 前景 F=150、背景 B=50、α=0.8，混合後的值是？
100
110
120
130
0.8 × 150 + 0.2 × 50 = 120 + 10 = 130。α 很大（0.8）所以結果靠近前景 150，合理。
